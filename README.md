# EvoTail

EvoTail is a **Phase 1 research scaffold** for testing a narrow hypothesis: does a
frozen protein language model perform worse on proteins with sparse observed
evolutionary support?  It does not yet train an "EvoTail" model.  The current code
builds an auditable support table, scores ProteinGym substitution assays with a
frozen ESM-2 masked language model, and tests the association between support and
per-assay zero-shot performance.

The broader research rationale, stop/go criteria, and the later continual-training
work are in [the research plan](docs/plans/2026-06-23-evotail-research-plan.md).

## What is implemented

| Component | What the code does |
| --- | --- |
| Evolutionary-support table | Validates protein sequences and combines the available `nearest_identity`, UniRef-style cluster-size, `msa_neff`, and `taxon_count` fields. Each available component is percentile ranked; their mean is `evolutionary_support_score` (higher = denser observed support). Missing component values are median-imputed and counted in a flag. |
| Strata and future sampling weight | Splits the score into quantile strata (`0` is lowest support) and writes a bounded, mean-normalized `tail_sampling_weight`. This produces metadata only; it does **not** sample training data. |
| ProteinGym scoring | Scores substitution-only variants with ESM-2 masked marginal log-likelihood ratios. For a multi-mutant, it scores each substituted position in the full mutant-sequence context and sums the ratios. |
| Support-gap analysis | Merges variant scores with the support table, computes one Spearman correlation per assay, bootstraps mean correlation within support strata, and fits a transparent OLS diagnostic with available length, mutation-depth, selection-type, and functional-category controls. |
| Cluster execution | Supplies three Slurm templates: support-table construction, one-array-task-per-assay scoring, and analysis/figure generation. |

`cluster_sequences.py` only constructs or runs explicit MMseqs2 clustering commands;
it does not derive the raw homology metadata automatically. Raw data, checkpoints,
and generated experiment results are deliberately excluded from Git.

## What is not implemented or established

- No actual ProteinGym, UniRef, MSA, or taxonomy dataset is included, and no
  scientific result has been generated by this repository.
- The repository does not yet implement the planned phylogenetic-information
  sampler, GroupDRO/CVaR objective, continual pretraining loop, EvoTail-Bench,
  leakage audit, or structure-conditioned extension.
- The default scorer is `facebook/esm2_t30_150M_UR50D`; a 650M experiment is not
  bundled or validated.
- The analysis uses EvoTail's own per-assay Spearman calculation. It does **not**
  invoke ProteinGym's official aggregation scripts, so it must not be described as
  leaderboard-equivalent without a separate convention check.
- The YAML files are reproducibility templates, not a Hydra-driven launcher; the
  current scripts take paths and runtime settings from their CLI arguments or Slurm
  environment variables.
- The fitted regression is an association/effect-size diagnostic, not a causal
  estimate. A positive `support_gap` means the highest-support stratum has a higher
  mean per-assay Spearman than the lowest-support stratum.

## Phase 1 workflow

1. Prepare a metadata table outside Git. `configs/data.yaml` records placeholder
   paths but is not parsed by the current scripts: pass paths as command-line
   arguments locally or export the environment variables used by the Slurm templates.
   The table needs unique `protein_id` and `sequence` columns, plus at least one of
   the optional evidence fields documented in
   [data/README.md](data/README.md).
2. Run `scripts/build_support_table.py` to create
   `artifacts/support/protein_support.parquet` (or another CSV/TSV/Parquet path).
3. Prepare a ProteinGym manifest with `DMS_id`, `assay_path`, `target_seq`, and
   `protein_id`; score each assay through `scripts/score_proteingym_assay.py` or
   `slurm/02_score_proteingym_array.sbatch`.
4. Run `scripts/analyze_support_gap.py` to write:
   - `per_assay_spearman.csv`
   - `support_stratum_summary.csv`
   - `support_gap_stats.json`
   - `figure1_support_gap.pdf` (unless `--skip-figure` is supplied)

The exact data contract and Slurm environment variables are documented in
[data/README.md](data/README.md) and [slurm/README.md](slurm/README.md).

## Local setup and verification

Use Python 3.10 or newer. Ensure `python` resolves to that interpreter; a Python 2
installation on `PATH` cannot parse this code.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -e .
python -m unittest discover -s tests -v
```

The unit tests use synthetic data and do not download models or datasets. `torch`
and `transformers` are only needed on a GPU node when running the ESM scoring script.
For CPU analysis and tests, install `requirements-cpu.txt` instead of
`requirements.txt`. GitHub Actions runs these tests on pushes to `main` and pull
requests using Python 3.12.

## Reproducibility rules

- Keep raw data, checkpoints, and generated results out of Git.
- Record source release date, input checksum, checkpoint revision, seed, total
  tokens, GPU hours, and Slurm job ID for every run.
- Treat missing evolutionary evidence as unknown, not automatically as tail evidence.
- Do not move to continual training until the Phase 1 association survives the
  pre-specified controls and stop/go criteria in the research plan.
